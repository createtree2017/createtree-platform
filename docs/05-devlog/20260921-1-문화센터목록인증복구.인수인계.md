# 2026-09-21 문화센터 목록 인증 복구 인수인계

## 배경과 결정

고객이 로그인 상태에서 신청한 문화센터 목록이 사라졌다가 재로그인 후 복구된다고 제보했다. 현재 코드에서 세션/JWT 인증 기준 차이, 목록 오류의 빈 배열 처리, 재조회 부족, 중복 갱신 API를 확인했다. 신청 데이터를 변경하는 대신 인증 복구와 조회/표시 흐름을 정리했다. 운영 장애 당시 로그는 미확보로, 단일 운영 원인 확정과 코드 결함 수정은 구분한다.

## 주의사항 및 사용자 영향

- 인증 복구 중 잠깐 대기할 수 있다. 기존 목록이 있으면 유지한다.
- 기존 사용자 중 세션과 갱신 토큰이 모두 없거나 만료된 경우 재로그인이 필요하다. 만료 JWT만으로 무기한 로그인시키지 않는다.
- 쓰기 요청은 자동 재전송하지 않는다. 따라서 신청/취소 등의 401은 사용자가 상태 확인 후 다시 시도해야 할 수 있다.
- 세션 저장소는 기존 메모리 방식 그대로다. 이번 변경은 갱신 토큰을 통해 JWT 인증을 복구하며 세션 전용 API 복원까지 포함하지 않는다.
- 공통 요청 함수 외의 별도 직접 fetch/API 클라이언트는 이번 자동 복구 적용 범위와 다를 수 있다.
- 빌드는 성공했지만 정적/동적 import 혼용 및 큰 번들 경고가 남아 있다.
- 로컬 Node 24.15.0에서 검증했다. package.json의 배포 환경 Node 20.x 실행 검증은 별도다.
- DB 스키마 변경, 운영 데이터 수정, 커밋/푸시/배포는 하지 않았다. 기존 미추적 `20260612-모바일크롬PWA앱홈스크롤불가수정.인수인계.md`는 그대로 보존했다.

## 후속: 순차 무결성 재검증 및 추가 수정

같은 대화의 후속 요청에 따라 이 문서에 통합 기록한다. 브라우저는 사용자의 명시적 제외 요청에 따라 실행하지 않았다.

### 추가 수정 내용과 이유

- 공통 요청 함수의 기존 쿼리 문자열 결합/Headers 객체·튜플 전달 오류를 수정했다.
- 로그인 복귀 URL 정규화 및 제어문자 검사를 보강하고, 인증 복구의 Authorization 형식을 목록 미들웨어와 동일하게 맞췄다.
- Firebase 요청의 `idToken` 계약 불일치를 수정했다. 로그인 성공 캐시 처리를 새 `client/src/lib/login-session.ts`, Firebase 요청을 새 `client/src/lib/firebase-session.ts`로 모았다.
- Firebase 서버 오류가 토큰 오류(401)로 오인되지 않도록 분리하고, 새 Passport 세션 저장 후 쿠키를 발급한다.
- `useMissionQueries`에서 목록 응답 구조를 검증하고 쿼리 옵션을 실제 런타임 객체로 테스트할 수 있게 했다.
- `client/src/pages/auth-handler.tsx`의 인증 응답 전체 로깅을 제거하여 새 토큰 응답 노출을 방지했다.

### 후속 검증 결과

- ✅ 기존 테스트 27개 통과 → 신규 경계 테스트 4개 실패 재현 → 수정 후 확장된 40개 모두 통과
- ✅ 실제 Passport/express-session + 로컬 HTTP + 프론트 요청 함수 연동 테스트
- ✅ 실제 QueryObserver의 복귀/재연결, 비활성 조건, 캐시 분리, 오류별 재시도 검증
- ✅ 전체 애플리케이션 타입 검사 및 신규 테스트 포함 별도 타입 검사
- ✅ 신규 테스트 fixture의 타입 오류 2건 발견 후 보완, 재검사 통과
- ✅ 프론트/서버 빌드
- ✅ client/server/shared/db/scripts의 TS·TSX 586개 파일 구문 오류 0
- ✅ 환경·스킬·npm 설치 의존성 검사, diff 공백 검사

기존 이미지 프록시 테스트는 Jest/supertest 미설치로 실행하지 않았다. 운영 데이터 변경/메일·푸시·AI 호출 스크립트는 실행하지 않았다. 빌드의 큰 번들/혼합 import 경고와 Node 24 로컬 대 Node 20 배포 환경 차이는 그대로다. 커밋/푸시/배포는 수행하지 않았다.
