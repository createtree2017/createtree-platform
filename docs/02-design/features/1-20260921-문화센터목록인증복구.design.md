# 문화센터 목록 인증 복구 설계

## 인증

서버의 인증 복구 서비스를 `/me`와 단일 `/refresh-token`에서 재사용한다. Passport 세션과 Google 서버 세션을 인정하되 DB에서 현재 사용자 및 탈퇴 여부를 확인한다. 세션이 없으면 검증된 refreshToken을 사용한다. 만료 JWT의 decode 결과만으로 재발급하지 않는다. 갱신 응답은 HttpOnly 쿠키와 accessToken을 함께 반환하여 기존 Bearer 클라이언트와 호환한다. 일반/Google 로그인은 기존 14일 갱신 토큰을 발급하며 로그아웃에서 무효화한다.

## 요청

GET/HEAD만 401 후 갱신 및 원 요청 1회 재실행한다. 동시 요청은 하나의 Promise를 공유한다. 갱신 실패가 통신/서버 오류이면 인증 만료로 단정하지 않는다. POST/PUT/DELETE 등 쓰기 요청은 자동 재전송하지 않는다. 요청 취소를 지원하고 로그인/로그아웃 경계에서 오래된 결과를 적용하지 않는다. 인증 요청 자체의 순환 재시도는 금지한다.

## 화면

문화센터 훅에 사용자/병원/권한별 쿼리 키와 활성 조건을 둔다. 복귀 및 재연결 시 오래된 조회를 갱신하고 일시적인 오류만 제한적으로 재시도한다. 처음 조회 실패는 오류 카드, 기존 데이터가 있으면 목록과 오류 안내를 함께 표시한다. 401에는 원래 경로를 저장하는 로그인 버튼을 표시한다. 로그인 완료 후 안전한 내부 경로로 복귀한다.

## 검증

Node 테스트 러너와 격리한 Express 서버/가짜 저장소로 만료, 삭제 사용자, 갱신 자격, 동시 요청, 쓰기 비재전송, 오류별 화면 상태를 검증한다. `npm run check`, `npm run build`, `npm run verify`, `git diff --check`를 실행한다. 실제 브라우저 검증은 프로젝트의 `!!테스트!!` 규칙에 따르고, 미수행 범위는 완료 보고에 명시한다.

## 구현 보완

- Firebase ID 토큰 로그인에도 같은 갱신 쿠키를 발급한다. Google OAuth 신규 로그인은 Passport 세션 재생성/저장을 거쳐 이전 계정 세션과의 혼선을 막는다.
- 유효 JWT만 있고 병원/권한이 변경된 경우에는 DB의 최신 정보를 반영하되 원래 JWT 만료시간을 유지한다.
- 로그인 상태 조회의 통신 오류는 인증 만료로 간주하지 않는다. 최초 인증 조회 실패 시 보호 화면에서 재시도를 안내한다.
- 기존 메모리 세션 저장소는 이번에 변경하지 않았다. 기존 계정의 세션/갱신 자격이 모두 사라졌다면 재로그인이 필요하다.

## 순차 무결성 재검증 보완

- 기본 요청 함수는 기존 쿼리 문자열과 Headers/튜플 형식을 보존한다.
- 로그인 복귀 URL은 제어문자/역슬래시를 거부하고 정규화한 내부 경로만 허용한다.
- 서버는 Bearer 형식과 JWT 서명을 함께 검증한다.
- Firebase 클라이언트는 검증 가능한 ID 토큰을 전달하고, 서버는 토큰 검증 실패(401)와 DB/세션 실패(500)를 구분한다. 새 Passport 세션 저장 후 쿠키를 발급한다.
- 로그인 성공 캐시/토큰 처리를 `applyLoginResult`로 통합하고, 문화센터 목록은 배열 및 기본 항목 구조를 확인한 후 화면에 전달한다.
- 실제 QueryObserver/focusManager/onlineManager 및 메모리 Passport 세션을 사용하는 로컬 HTTP 테스트를 추가한다. 브라우저와 실제 외부 인증/운영 DB는 사용하지 않는다.
