# 회원 문의 관리 개발 및 코드 검증 보고

## 결과

승인된 최소 범위를 구현했다. MY → 문의사항에서 회원이 비공개 문의를 작성하고, 관리자 `/admin?tab=inquiries`에서 문의를 확인·답변한다. 문의 1건당 답변 1개를 수정할 수 있다. 운영 Railway DB에 새 테이블만 추가했으며 운영 사이트 코드 배포는 수행하지 않았다.

## 계획 대조

| 요구 | 구현·확인 |
| --- | --- |
| 회원 문의 작성 | 제목 1~100자, 내용 1~3000자, 서버 작성자 지정, 공백/초과/임의 필드 거부 |
| 내 문의 목록/상세 | 사용자별 캐시·SQL 소유권 조건, 최신순 20개 더 보기, 제목/일시/상태 |
| 관리자 대메뉴 | 회원관리 옆 문의사항 탭, 기본 전체, 대기/완료 필터, 페이지 이동 |
| 관리자 답변 | 1~3000자, 최초 답변 시각 유지, 수정 시각/담당자 갱신, 저장 원자적 처리 |
| 비공개 권한 | 현재 DB 회원 확인, admin/superadmin만 관리, 병원 관리자 본인 문의만 |
| 오류/모바일 | 입력 초안 보존, 중복 클릭 억제, 조회 오류/빈 상태 구분, 모바일 카드와 탭 줄바꿈 |
| 범위 제한 | 비회원·첨부·추가 댓글·알림·사용자 수정/삭제 제외 |

## 검증

- `npm run test:inquiries`: 25개 통과(미확인 답변 후속 포함, HTTP/DB 부모 테스트 포함).
- `npm run test:auth-recovery`: 기존 40개 통과.
- Node v20.20.2에서 위 4개 테스트 파일을 함께 실행: 총 65개 통과, 실패/건너뜀 0.
- PostgreSQL 테스트는 단일 연결의 `pg_temp` users/customer_inquiries를 사용하고 rollback한다. 실제 운영 회원/문의 데이터에 테스트 데이터를 삽입하지 않았다.
- 검증 경계: 미인증/위조/만료/탈퇴/없는 회원, 회원 간 접근 차단, 병원 관리자와 권한 하향된 관리자의 옛 JWT 차단, 입력 화이트리스트, 페이지/ID/필터 오류, 정상 생성/답변/수정, SQL CHECK/FK 위반, DB 장애 503 및 내부 정보 비노출.
- 프론트 코드 검증: HTML 입력 텍스트 렌더링, 캐시 키·초안 격리, 읽기 인증 복구, 쓰기 비재전송, 권한 상실 시 캐시 미표시, 잘못된 JSON/HTML/503 오류 처리.
- `npm run check -- --pretty false` 통과.
- 기본 tsconfig에서 빠지는 신규 테스트 및 운영 확인 스크립트까지 포함한 TypeScript Compiler API 검사: 오류 0.
- `npm run build`: 프론트·서버 빌드 통과. 기존 대형 청크/정적·동적 import 혼용 경고는 남아 있다.
- `npm run skills:sync`, `npm run verify`(skills:check 포함) 통과.
- `git diff --check` 및 신규 코드 13개 파일의 줄끝 공백 검사 통과.

## 발견 및 보완

1. 페이지 입력 스키마에서 Zod default 후 regex 호출 순서의 타입 오류를 발견해 바로잡았다.
2. JSX의 독립 Node 렌더링 테스트에서 React import 누락을 발견해 명시했다.
3. JSON body-parser가 primitive null을 라우트 이전에 거부하는 테스트 fixture를 교정하고, 배열·타입 오류 등 실제 라우트 계약 위반을 검증했다.
4. 추가 검토에서 권한 상실 후 남는 캐시를 401/403/404 시 숨기고, 취소된 조회를 재시도하지 않도록 보완했다.
5. 관리자 탭 추가로 모바일 줄바꿈 시 고정 높이와 겹칠 가능성을 제거했다.

## DB 반영

- SQL: `db/migrations/20260922_create_customer_inquiries.sql`
- 적용: `npx tsx scripts/apply-customer-inquiries.ts --apply`
- 검증: 같은 스크립트 기본 실행은 읽기 전용. 새 테이블 9컬럼, 4인덱스 및 제약을 확인했다.
- 전체 `drizzle push --force` 대신 승인된 새 테이블/인덱스 SQL만 트랜잭션으로 적용했다. 기존 테이블과 회원/미션 데이터는 변경하지 않았다.
- `npx tsx scripts/verify-customer-inquiries.ts`: 새 Express 프로세스에서 실제 운영 어댑터·JWT 쿠키·DB로 GET만 수행. 무인증 401, 본인/관리자 목록 200 JSON, 일반회원 관리접근 403 확인.

## 검증 범위와 후속

브라우저 실행과 운영 코드 배포는 하지 않았다. 따라서 실제 모바일 레이아웃/키보드/터치 및 운영 전체 앱에서의 최종 사용 흐름까지 무결점을 보장하는 결과는 아니다. 코드 기반으로 수행한 검증에서는 미해결 실패가 없다.

코드 배포 후 MY → 문의 작성 → 관리자 답변 → 사용자 답변 확인 순서로 화면 검증한다. 로컬 브라우저 확인 시 프로젝트 규칙대로 `/api/dev/auto-login`에서 시작한다. `!!푸시!!` 없이 git add/commit/push를 수행하지 않았다.

## 후속: 미확인 답변 뱃지

MY 문의사항에 나의 알림과 같은 빨간 숫자 뱃지와 N개 안읽음 안내를 추가했다. 문의 목록에는 새 답변을 표시한다. 사용자 상세에서 답변이 표시되고 탭이 보이는 경우에만 PUT으로 읽음을 저장한다. 숫자는 서버에 저장되어 기기 간 공유되며 답변 수정은 다시 미확인으로 계산한다. 기존 답변은 새 기능 도입 시 미확인으로 초기화한다.

DB 후속 migration `20260922_add_inquiry_read_revisions.sql`을 적용했다(현재 11컬럼/5인덱스). 문의 본문/답변은 변경하지 않고 버전 메타데이터만 추가했다. 버전별 읽음 테스트로 지연 요청이 새 답변을 읽음 처리하거나 이전 읽음 상태로 되돌리는 것을 막았다. 미확인 숫자 API와 읽음 API는 회원 소유권을 검증한다.

로컬 5000 서버의 이전 프로젝트 프로세스를 확인 후 재시작했다. 새 프로세스에서 `/api/inquiries/unread-count` 200 및 미확인 1건, 목록의 버전/미확인 필드 응답을 확인했다. 운영 코드 배포·브라우저 자동 실행은 하지 않았다.
